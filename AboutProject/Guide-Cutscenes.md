# راهنمای کات‌سین‌ها، منوی بچگی، و ساختن خروجی

**پروژه:** نخِ قرمزِ پوسیده
**این فایل جواب سه سؤال است:** کات‌سین‌ها چطور کار میکنند، منو بعد از تمام شدن بازی چه میشود، و چطور دیالوگ‌ها را عوض کنم و خروجی بگیرم.

## ۰. اول از همه — یک دکمه که همه چیز را آماده میکند

```
The Frayed Red String ▸ Prepare The Whole Game
```

این کار را میکند، به همین ترتیب:

| # | کار |
|---|---|
| ۱ | ساختن پوشه‌های لازم (`Story/Acts`، `Audio/Voice`، `Video`، `StreamingAssets/Video` و …) |
| ۲ | ساختن دوباره‌ی همه‌ی کتابخانه‌ها: تصویر، صدا، ویس، ویدیو، UI |
| ۳ | برگرداندن جای کاراکترها روی عددهای طراحی |
| ۴ | باز کردن **تک‌تک** Scene های پرده‌ها، درست کردنشان، و مرتب کردن Marker ها |
| ۵ | ساختن اسکریپت پرده‌های ۲ تا ۷ + هر دو پایان |
| ۶ | ساختن دوباره‌ی Act Library |
| ۷ | درست کردن Build Settings |
| ۸ | درست کردن Player Settings (اسم بازی، رزولوشن، …) |
| ۹ | بررسی ماژول Video |

بعدش خودش گزارشِ کامل چاپ میکند.

**یک بار میپرسد** و فقط یک چیز: اگر پرده‌ای از قبل دیالوگ داشته باشد، آن‌ها را نگه دارد یا از روی سند دوباره بنویسد. پیش‌فرض **نگه داشتن** است.

> دوباره زدنش هیچ ضرری ندارد. هر وقت چیزی خراب به‌نظر رسید، اول این را بزن.

بعدش:
```
The Frayed Red String ▸ Is The Game Ready?
```
لیستِ زنده‌ی هر فایلی که هنوز نیست.

## ۰.۵ تصویرِ محو — کجا خاموش و روشنش کنی

**بله عمدی است.** اسمش «پرده» (Veil) است و همان چیزی است که سند بهش میگوید «شیشه‌ی تار»: پرده‌های ۱ تا ۴ از پشتش دیده میشوند و **پرده‌ی پنجم برش میدارد**. این کلِ معنیِ «گرافیک واقع‌گرایانه میشود» در بازی‌ای است که قرار نیست سه‌بعدی شود — همان آرت، بدون چیزی جلویش.

### کجا کنترلش کنی

```
Story Editor ▸ تب Stage ▸ بخش Veil
```

سه فیلد، و پیش‌نمایشِ زیرش **همان لحظه** نشانت میدهد:

| فیلد | یعنی چه |
|---|---|
| `Veil Enabled` | تیکش را بردار → بازی از فریمِ اول کاملا شفاف |
| `Veil Strength` | `0` تا `1`. پیش‌فرض `0.55` |
| `Veil Colour` | رنگ و Alpha اش. پیش‌فرض صورتیِ کم‌رنگ |

> قبلا این عدد داخل کد ثابت بود و روی **قدرتِ کامل** بود — به همین دلیل کلِ بازی کمی از فوکوس خارج به‌نظر میرسید. حالا هم قابل تنظیم است و هم پیش‌فرضش ملایم‌تر.

### اگر کاملا خاموشش کنی چه میشود

هیچی نمیشکند. Beat های `Grade` داخل پرده‌ی پنجم چیزی برای برداشتن ندارند، پس آن یک لحظه‌ی «تصویر شفاف شد» را از دست میدهی و بس. بقیه‌ی بازی دقیقا مثل قبل.

### کجا در کد است

| چه چیزی | کجا |
|---|---|
| خودِ لایه | `_C#/Presentation/StoryGrade.cs` |
| عددهایش | `StageSettings.asset` (تب Stage) |
| برداشتنش در پرده ۵ | Beat از نوع `Grade` با `Amount = 0` |
| لایه‌ی خون هم همین‌جاست | `Stain` |

## ۱. جای کاراکترها — دیگر خراب نمیشود

عددهای رسمی:

| | X | Y | Scale |
|---|---|---|---|
| **یوآ** | `-4.55` | `-1.5` | `0.48` |
| **هارو** | `4.70` | `-1.5` | `0.50` |
| یوآ (۹ ساله) | `-4.55` | `-1.5` | `0.335` |
| هارو (۹ ساله) | `4.70` | `-1.5` | `0.350` |

### دلیلِ آخرین باری که خراب شد (و درست شد)

`AmbientMotion` — همان چیزی که باعث میشود همه چیز آرام نفس بکشد — **لحظه‌ای که فعال میشود، جای فعلیِ آبجکت را به‌عنوان «جای استراحت» ذخیره میکند** و بعد هر فریم همان را دوباره مینویسد.

من موقعِ اضافه کردنِ کاراکترهای بچه ترتیب را عوض کرده بودم: `AmbientMotion` **قبل** از جایگذاری اضافه میشد. پس جای `(0, 0)` را ذخیره میکرد و از فریمِ بعد هر دو کاراکتر را میکشید وسطِ پایینِ صفحه — با ارتفاعِ کاملِ ۱۲۴۴ واحد. **دقیقا همان چیزی که دیدی: هر دو، بزرگ، وسط.**

عددهای داخل asset تمامِ این مدت درست بودند و شصت بار در ثانیه بازنویسی میشدند.

حالا جایگذاری **قبل** از اضافه شدنِ `AmbientMotion` انجام میشود، و اگر جای یک کاراکتر وسطِ پرده عوض شود (پرده‌ی ششم، دو سنِ یک نفر) `RecapturePosition()` صدا زده میشود.

**برای دیدنِ حقیقت هر وقت شک کردی:**
```
The Frayed Red String ▸ Diagnose Character Placement
```
هم توی حالت Play و هم بیرونش کار میکند. میگوید asset چه میگوید، و اگر بازی در حال اجراست، Rect واقعا کجاست — و اگر این دو با هم نخوانند صریح مینویسد که چیزی دارد رویش مینویسد.

**چرا قبل‌ترش خراب میشد:** جای کاراکتر دو تا منبع داشت — عددهای داخل `StageSettings.asset` و Sprite هایی که داخل Scene گذاشته شده بودند. بازی موقع اجرا Scene را ترجیح میداد. یعنی یک Marker که کسی تکانش داده بود، یا Scale اش عوض شده بود، یا از یک Scene کپی‌شده مانده بود، کلِ کاراکترهای آن پرده را جابه‌جا میکرد — و توی Scene View هیچ نشانه‌ای نداشت.

**حالا:** بازی **فقط** عددهای `StageSettings` را میخواند. Marker های داخل Scene خوانده نمیشوند و فقط به‌عنوان مرجعِ چشمی آنجا میمانند (خاموش).

اگر بازش خواستی: تب **Stage** ← تیکِ `Read Placement From Scene`. توصیه نمیشود.

**جا را کجا تنظیم کنی:** `Story Editor ▸ تب Stage`. یک پیش‌نمایشِ واقعیِ ۱۶:۹ دارد که **همان ریاضی موتور بازی** را اجرا میکند.

## ۲. کات‌سین‌ها

### ۲.۱ پرده‌ی پنجم — شکستن UI

چهار اتفاق، با چند خط فاصله، به همین ترتیب. همه‌شان Beat هستند و داخل Story Editor قابل جابه‌جایی:

| ترتیب | Beat | چه میکند |
|---|---|---|
| ۱ | `PullDownDialogue` | هارو باکس دیالوگ را **میکشد** پایین. محو نمیشود، حرکت میکند، و تا دو سومِ راه مات است. |
| ۲ | `OpenFrame` | قاب باز میشود، تصویر کلِ پنجره میشود |
| ۳ | `Grade` (به ۰) | پرده‌ی صورتی برداشته میشود |
| ۴ | `SayVoiced` | از اینجا خط‌ها اسم فایل صدا دارند |

**بعد از `PullDownDialogue` باکس دیگر برنمیگردد.** خط‌های بعدی به شکل **زیرنویسِ ساده** روی تصویر می‌آیند — بدون پنل صورتی، بدون پلاک اسم.

> ⚠️ **درست قبل از `PullDownDialogue` هیچ‌وقت `Hold` نگذار.** `Hold` باکس را محو میکند، پس هارو یک صفحه‌ی خالی را میکشد پایین.

بعدش `Stain` (خون) و `CutMusic` (قطعِ آهنگ در یک فریم).

### ۲.۲ پرده‌ی ششم — حالت فیلم

اولین Beat پرده `EnterCinema` است. از آنجا:

- هر خط **به اندازه‌ی خواندنش** میماند و خودش میرود (۱.۶ تا ۹ ثانیه، از روی تعدادِ حرفِ همان زبان)
- کلیک و Space **هیچ کاری نمیکنند**
- فلشِ «منتظرِ توام» نمایش داده نمیشود
- اگر خط صدای ضبط‌شده داشته باشد، **طولِ فایل صدا برنده است**
- **Esc همچنان کار میکند** — منو و Save/Load باز میشوند

زمانِ تخمینیِ کل پرده: **حدود ۹ دقیقه و ۲۰ ثانیه**.

> داخل حالت فیلم **Choice نگذار** و **سکوتِ شمرده‌شده هم نگذار**. تب Check هر دو را به‌عنوان خطا میگیرد.

**مونتاژ آخر پرده** با `CutTo(...)` ساخته شده — برشِ آنی، بدون Fade و بدون صدای زنگ. فاصله‌ها هر بار کوتاه‌تر میشوند. این فقط چون بازیکن نمیتواند کلیک کند کار میکند: هر برش دقیقا روی همان فریمی می‌افتد که برایش نوشته شده، برای همه، هر بار.

### ۲.۳ پرده‌ی هفتم — ویدیو

Beat از نوع `Video`، فیلد `Film` = **`Act07Credits`**

دو جا دنبالش میگردد:

1. `Assets/Video/Act07Credits.mp4` — وارد Build میشود
2. `Assets/StreamingAssets/Video/Act07Credits.mp4` — **این را توصیه میکنم**؛ فایل، فایل میماند و بدون Import دوباره میتوانی تدوینش را عوض کنی

**نیاز به ماژول Video یونیتی دارد.** این پروژه ندارد:
`Window ▸ Package Manager ▸ Built-in ▸ Video ▸ Enable`
بررسی: `The Frayed Red String ▸ Check The Video Module`

> بدونِ ماژول بازی **کامپایل میشود** و پرده‌ی هفتم بدونِ فیلم اجرا میشود. هیچ چیزی نمیشکند.

پرده‌ی هفتم در دو Beat اولش `OpenFrame` و `Grade(0)` دارد — چون قاب و پرده‌ی صورتی برای **هر Scene از نو ساخته میشوند** و بدون آن‌ها پرده‌ی هفتم با قابِ بسته شروع میشد، انگار پرده‌ی پنجم اتفاق نیفتاده.

## ۳. ۵ دقیقه سکوت — چه چیزی روی صفحه می‌افتد

وقتی بازیکن روی یک خطِ «سکوت» دست به هیچی نمیزند:

| چه چیزی | جزئیات |
|---|---|
| **ضربان قلب** | از هر ۱۲ ثانیه شروع میشود و تا هر ۵ ثانیه نزدیک میشود. برای **همه** پخش میشود، حتی اجرای مخلوط. |
| **حرکت** | کاراکترها، پس‌زمینه و باکس همه نفس میکشند (Ambient Motion). هیچ‌وقت متوقف نمیشود. |
| **پرده‌ی صورتی** | ۶٪ گرم‌تر (پایان خوب در راه) یا سردتر (نرمال). روی اجرای مخلوط **هیچ تغییری نمیکند**. |

ضربان قلب عمداً برای همه پخش میشود: اگر فقط برای اجراهای واجدِ شرایط بود، بازیکن از روی سکوت میفهمید که اجرایش هنوز شانسی دارد یا نه — و این تنها چیزی است که این مکانیزم نباید لو بدهد.

## ۴. منوی بچگی

بعد از **هر** پایانی (تلخ، نرمال، خوب):

1. سیو‌ها کاملا پاک میشوند
2. یک فلگ در `PlayerPrefs` ثبت میشود — **این سیو نیست**، چیزی نمیدهد، و بازیِ بعدی باز هم از صفر شروع میشود
3. منوی اصلی عکسِ بچگی را نشان میدهد

**فایلی که باید بگذاری:**
```
Assets/Images/Backgrounds/MainMenuChildhoodImage.png
```

جایگزینِ Sprite روی `MainMenuBackGrundYuaAndHaruImage` میشود. تا وقتی نباشد، منو همان عکسِ همیشگی را نگه میدارد و یک خط داخل Console مینویسد.

**تستش:** بعد از دیدن یک پایان، برگرد به منو. برای برگرداندنش به حالت اول، `StoryProgress.Forget()` را صدا بزن یا `PlayerPrefs` را پاک کن.

## ۵. عوض کردن دیالوگ‌ها

**تنها جایی که لازم است:** `The Frayed Red String ▸ Story Editor` ← تب **Script**

- سه زبان کنار هم، داخل همان پنجره
- بالای پنجره یک انتخابگر **Language** هست؛ عوضش کن، کل پرده به همان زبان
- ترجمه‌ی خالی = بازی انگلیسی را نشان میدهد و کرش نمیکند
- دکمه‌ی **▶ Play from here** روی هر Beat، از همان‌جا بازی را شروع میکند

> ⚠️ **بعد از اینکه دیالوگ‌ها را عوض کردی، `Build Act NN From The Story Document` را دیگر نزن.** آن دستور همه چیز را از روی کد دوباره مینویسد و کارِ تو را پاک میکند.
> `Prepare The Whole Game` این را میپرسد و پیش‌فرضش **نگه داشتن** است.

اگر میخواهی دیالوگ‌ها را در کد نگه داری (تا `Prepare` هم بازنویسیشان کند)، فایلِ `_C#/Editor/ActNNBuilder.cs` را عوض کن و بعد Build را بزن.

## ۶. گرفتن خروجی

```
1. The Frayed Red String ▸ Prepare The Whole Game
2. The Frayed Red String ▸ Is The Game Ready?     ← لیست فایل‌های غایب
3. File ▸ Build Settings ▸ WarningScene باید Index 0 باشد
4. Build
```

`Prepare` این‌ها را خودش تنظیم میکند:

- اسم بازی: `The Frayed Red String`
- رزولوشن پیش‌فرض: `1920 × 1080`
- پنجره قابل تغییر اندازه
- **Run In Background روشن** — بازی روی زمانِ Unscaled اجرا میشود و پشتِ منو هم نفس میکشد؛ اگر با از دست دادن فوکوس متوقف شود، وسط یک خط می‌ایستد

**بازی بدونِ هیچ فایلِ هنری‌ای هم خروجی میگیرد و از اول تا آخر اجرا میشود.** پس‌زمینه‌های غایب تصویرِ جانشین میشوند، اسپرایت‌های غایب سایه، ویس‌های غایب تایپ‌رایتر، ویدیوی غایب رد میشود.

## ۷. تست کردن

| چه چیزی | چطور |
|---|---|
| کل بازی از اول | `Play The Whole Game` (یا `Alt+G`) |
| یک صحنه‌ی مشخص | Story Editor ← Beat ← `▶ Play from here` |

| چه چیزی کم است | `Is The Game Ready?` |
| اشکالات یک پرده | Story Editor ← تب **Check** |

همه‌ی ابزارهای `Endings ▸ Pretend…` داخل `#if UNITY_EDITOR` هستند و از Build کاملا حذف میشوند.
