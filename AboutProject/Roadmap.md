ترتیبِ فعلی روی صفحه:

```
یوآ:       هاروپی، نونوایی رو که تو نساختی.     ← آخرین بارِ پسوند
Hold(1.2)
همکلاسی:   اِ — شما دوتا اول-الفین.
هارو:      آره.
همکلاسی:   شما کنارِ پنجره می‌شینین. من دو ردیف عقب‌ترم، بغلِ قفسه‌ی کتاب.
یوآ:       همون قفسه‌ای که جلدِ چهار روشه.        ← حرف درباره‌ی مانگا
همکلاسی:   ...الآن چی صداش کردی؟
یوآ:       هیچی.
همکلاسی:   نه جدی، اون چی بود؟
یوآ:       مالِ خودمونه.
```

بازیکن آخرین بار شش کادر قبل‌تر «هاروپی» را شنیده و درست قبل از سؤالِ همکلاسی، حرف از **مانگا** بوده. پس «الآن چی صداش کردی؟» به مانگا می‌چسبد، نه به پسوند. «مالِ خودمونه» هم درباره‌ی مانگا خوانده می‌شود.

**درست کردنش:** پسوند باید **در حضورِ همکلاسی و بلافاصله قبل از سؤالش** گفته شود. خطِ مانگا یا باید برود، یا باید قبل از ورودِ همکلاسی بیاید.

> این را با نوشتنِ دوباره‌ی صحنه درست کن، نه با جابه‌جا کردنِ دو خط. دستورنامه بخشِ ۱۹ الگوی دقیقش را دارد.

### چرا لازم است

سه دلیل، به ترتیبِ اهمیت:

1. **پرده‌ی دوم یازده هفته طول می‌کشد** و روی صفحه پنج روزِ پشتِ سرِ هم به‌نظر می‌رسد. «۲۱ دسامبر» — روزی که هارو داستانِ خودکشی را تعریف می‌کند — بی‌معنی می‌ماند مگر بازیکن بداند از اکتبر تا حالا چقدر گذشته.
2. **ریاضیِ ۷/۸/۹ در پرده‌ی چهارم** بدونِ اینکه بازیکن تاریخِ امروز را دیده باشد، فقط سه عددِ تصادفی است. و ۲۶ ژانویه‌ی ۲۰۲۵ فقط وقتی کار می‌کند که بازیکن در پرده‌ی ششم ۲۶ ژانویه‌ی ۲۰۱۷ را ببیند و **خودش** بفهمد.
3. **دو پایانِ مخفی روی تاریخِ دستگاه سوارند.**

### تکه‌ی ۱ — `Narrative/StoryCalendar.cs` (فایلِ جدید)

```csharp
/// <summary>یک روز در تقویمِ داستان.</summary>
[Serializable]
public struct StoryDate
{
    public int Year;
    public int Month;   // ۱ تا ۱۲
    public int Day;     // ۱ تا ۳۱، صفر یعنی «تاریخی ست نشده»

    public bool IsSet => Year > 0 && Month > 0 && Day > 0;
}

public enum DateStyle
{
    Full,       // با روزِ هفته — کارتِ عنوانِ پرده
    Short,      // بدونِ روزِ هفته — مهرِ گوشه‌ی صفحه
    YearOnly    // برای پرش‌های بلندِ پرده‌های ۱۲ و ۱۳
}

public static class StoryCalendar
{
    public static string Format(StoryDate date, GameLanguage language, DateStyle style);
    public static DayOfWeek WeekdayOf(StoryDate date);
}
```

**قانونِ سخت: روزِ هفته هیچ‌وقت تایپ نمی‌شود، محاسبه می‌شود.** تنها راهِ اینکه دیگر «۱ سپتامبر ۲۰۲۴، دوشنبه» نوشته نشود — که یکشنبه است.

سه اجرای بومی، نه سه ترجمه:

| زبان | `Full` | `Short` |
|---|---|---|
| fa | `دوشنبه ۲ سپتامبر ۲۰۲۴` | `۲ سپتامبر ۲۰۲۴` |
| ja | `2024年9月2日（月）` | `2024年9月2日` |
| en | `Monday, 2 September 2024` | `2 September 2024` |

فارسی **ارقامِ فارسی** می‌گیرد و ژاپنی و انگلیسی ارقامِ لاتین. ماه‌ها میلادی‌اند — داستان در ژاپن می‌گذرد، تقویمِ هجری هیچ‌جا نمی‌آید.

> از `System.Globalization` استفاده نکن. جدولِ اسمِ ماه‌ها را خودت بنویس: خروجیِ `DateTime.ToString` به کالچرِ دستگاهِ بازیکن وابسته است و همان بازی روی دو کامپیوترِ متفاوت دو چیزِ متفاوت نشان می‌دهد.

* **کارتِ عنوانِ پرده** — `StoryOverlayView.PlayTitleCard` الآن `seasonNumber` و `actName` می‌گیرد و یک خطِ «فصل» بالای عنوان دارد. تاریخ **زیرِ** خطِ جداکننده می‌نشیند، ریزتر و کم‌رنگ‌تر، با `DateStyle.Full`.
* **بیتِ `DateCard`** — مهرِ کوچکی در همان گوشه‌ای که `Caption` می‌آید، با `DateStyle.Short`، حدودِ ۲ ثانیه. منتظرِ بازیکن نمی‌ماند، دقیقاً مثلِ `Caption`.

**قانون‌ها:**

* تاریخ **فقط وقتی می‌آید که عوض شده باشد.** یک `DateCard` در هر جهشِ زمانی، نه سرِ هر صحنه.
* **هیچ شخصیتی هیچ‌وقت تاریخ را بلند نمی‌گوید.** تاریخ کارِ رابطِ کاربری است. «امروز بیست‌ویکم دسامبره» دیالوگ نیست، اعلامِ وضعیت است — دستورنامه بخشِ ۹، الگوی ممنوعِ ۳.
* `DateCard` باید در `ReplayStageBeats` هم یک `case` بگیرد تا لودِ سیو تاریخِ درست را برگرداند.
* **در حالتِ فیلم (پرده‌ی ششم) تاریخ نمی‌آید** مگر به‌عنوانِ یک برشِ عمدی. آنجا تاریخ خودش یک افشاست: ۲۶ ژانویه ۲۰۱۷.

### تکه‌ی ۳ — ساعتِ سیستم، برای دو پایانِ مخفی

یک بار موقعِ بالا آمدن (`GameBootstrap` یا `MainMenuSceneController`):

```
اگر تاریخِ محلیِ دستگاه == ۲۶ ژانویه ۲۰۱۷  → دکمه‌ی Start مستقیم پرده‌ی ۶ و بعد ۷ را می‌برد → پایانِ «تماشا»
اگر تاریخِ محلیِ دستگاه == ۲۶ ژانویه ۲۰۱۶  → خطِ داستانیِ K-Sei → پایانِ «هیچ اتفاقی نیفتاد»
```

* **ساعتِ محلی، نه UTC.** بازیکن ساعتِ دستگاهِ خودش را عوض می‌کند.
* **فقط یک بار خوانده شود، موقعِ بالا آمدن.** نه هر فریم، و نه وسطِ بازی — وگرنه عوض شدنِ تاریخ در نیمه‌شب، وسطِ یک اجرای معمولی، چیزی را باز می‌کند.
* پرده‌ی ۲۶ ژانویه ۲۰۱۶ به K-Sei وصل است که هنوز وجود ندارد. **فعلاً فقط ۲۰۱۷ پیاده شود** و ۲۰۱۶ یک `TODO` با یادداشتِ صریح بماند.

### قانون‌های حرکت

* حرکت از کانال‌های `AmbientMotion` رد شود، نه مستقیم روی transform — **قانونِ ۱ موتور.**
* سرعتِ پایین آمدن تصادفی در یک بازه‌ی باریک؛ اگر همه هم‌سرعت باشند، شبیهِ باران می‌شود.
* تابِ افقی: سینوسی، با فازِ تصادفیِ هر ذره.
* برگ‌ها دَوَران هم دارند، گلبرگ‌ها خیلی کم، برف اصلاً.
* **چگالی کم.** یک لایه‌ی پرذره، کلِ فضاسازی را به یک اسکرین‌سیور تبدیل می‌کند.
* روی `StoryClock` باشد، پس با منوی توقف می‌ایستد.
* موقعِ `EnterAside` (حرف زدن با بازیکن) و در حالتِ فیلم باید بتواند خاموش شود. وقتی یوآ با بازیکن حرف می‌زند، اتاق چیزی نباید داشته باشد که حواس را پرت کند.

### از کجا فصلش را می‌فهمد

از **پس‌زمینه**، نه از پرده — تا یک پرده بتواند چند فصل داشته باشد و انتخاب یک‌جا نوشته شود:

```csharp
// یک جدولِ کوچک کنارِ ثابت‌های Backgrounds
AutumnSchoolAlleyDay        → MapleLeaf، چگالیِ کم
CherryBlossomSchoolAlleyDay → Sakura   ← فقط در فلش‌بکِ شاد و پایانِ رویا
همه‌ی بقیه                   → None
```

و یک راهِ صریح برای وقتی که یک صحنه می‌خواهد چیزِ دیگری باشد. ساده‌ترینش: بیتِ `DateCard` و `Background` هیچ‌کدام این را نمی‌دانند — یک `SeasonalFall.Set(kind, density)` که از یک بیتِ اختیاری صدا زده شود، یا (بهتر) جدولِ پس‌زمینه به‌علاوه‌ی یک override در همان بیتِ `Background`.

> **تصمیمِ طراحی را قبل از نوشتنِ کد بپرس.** دو راهِ بالا به دو API متفاوت می‌رسند و عوض کردنشان بعداً گران است.
